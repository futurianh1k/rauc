# 로봇 개발 지침

공통 규칙은 [rules.md](../rules.md)를 따른다. 이 문서는 로봇(자율 이동체, 매니퓰레이터 등) 소프트웨어를 만들 때 추가로 지킬 내용이다.

## 1. 목적

인지, 판단, 제어 소프트웨어를 시뮬레이션에서 검증한 뒤 실제 장비로 안전하게 옮긴다.

## 2. 적용 범위

| 대상 | 내용 |
| --- | --- |
| HPC | ROS 2 노드(인지, 위치 추정, 경로 계획), 센서 드라이버, 시뮬레이션 |
| MCU | 저수준 제어(모터, 비상정지), 센서 인터페이스 |
| 플랫폼 | `TODO(확인 필요)`: 로봇 종류, ROS 2 배포판, 시뮬레이터 |
| 제외 | 모델 학습(→ [ai-ml.md](ai-ml.md)) |

## 3. 설계 원칙

- **안전 정지는 소프트웨어 스택과 독립적이어야 한다.** 비상정지는 MCU 또는 하드웨어 회로에서 처리한다. ROS 2 노드가 멈춰도 로봇은 정지해야 한다.
- **실시간 제어는 MCU에서, 판단은 HPC에서 한다.** HPC에서 MCU로 가는 명령에는 타임아웃(워치독)을 두고, 명령이 끊기면 MCU가 감속·정지한다.
- **노드 간 계약을 명시한다.** 토픽 타입, QoS(신뢰성, 이력, 데드라인), 좌표계(REP 103/105)를 [인터페이스 정의서](../templates/interface.md)에 적는다.
- **시뮬레이션과 실제 장비가 같은 코드를 쓴다.** 차이는 launch 파라미터와 드라이버로만 둔다.
- **재현 가능하게 기록한다.** 실험은 rosbag2로 기록하고, 코드 커밋과 파라미터를 함께 남긴다.

## 4. 구현 체크리스트

- [ ] 노드마다 입력 토픽 타임아웃 시 동작을 정의했다
- [ ] QoS가 발행·구독 양쪽에서 호환된다
- [ ] 좌표계(`map`, `odom`, `base_link`)와 TF 트리가 REP 105를 따른다
- [ ] 속도·가속도·작업 영역 제한을 MCU에서도 한 번 더 확인한다
- [ ] 파라미터 기본값이 안전한 쪽(저속)으로 설정돼 있다
- [ ] 비상정지 경로가 ROS 2를 거치지 않는다
- [ ] launch 파일로 시뮬레이션·실제 장비를 전환할 수 있다

## 6. 관련 표준 (참고·준용 수준)

## 7. 흔한 실수

- QoS가 맞지 않아 메시지가 조용히 전달되지 않는다 (reliable 구독, best-effort 발행).
- 시뮬레이션 시간(`use_sim_time`)과 실제 시간이 섞인다.
- 비상정지를 ROS 2 토픽으로만 구현한다.
- 단위(도/라디안, mm/m)가 노드마다 다르다.
- rosbag 없이 실험해 문제를 재현하지 못한다.
