# AI 개발 지침

공통 규칙은 [rules.md](../rules.md)를 따른다. 이 문서는 데이터 수집부터 학습, 엣지(HPC) 배포, 업데이트까지 AI 기능을 만들 때 추가로 지킬 내용이다.

## 1. 목적

재현할 수 있는 방법으로 모델을 만들고, 차량·로봇에서 안전하게 실행하며, OTA로 갱신하고 되돌릴 수 있게 한다.

## 2. 적용 범위

| 대상 | 내용 |
| --- | --- |
| 데이터 | 수집, 라벨링, 비식별화, 버전 관리 |
| 학습 | 실험 관리, 평가, 모델 선택 |
| 배포 | HPC 엣지 추론(변환, 양자화, 최적화), OTA 배포 |
| 운영 | 성능 모니터링, 재학습 |
| 프레임워크·런타임 | `TODO(확인 필요)`: PyTorch, ONNX Runtime, TensorRT 등 |

## 3. 설계 원칙

- **AI 출력은 단독으로 안전 결정을 내리지 않는다.** 제동·조향 같은 안전 기능에 쓸 때는 규칙 기반 검사나 다른 센서와 교차 확인하고, MCU 측 안전 장치가 최종 판단한다.
- **모든 모델은 재현할 수 있어야 한다.** 데이터셋 버전, 학습 코드 커밋, 하이퍼파라미터, 시드, 환경을 기록한다.
- **평가 세트는 학습에 쓰지 않는다.** test 분할은 고정하고, ODD 조건별(야간, 우천 등)로 따로 평가한다.
- **배포 가능한 모델은 타깃 장치에서 측정한 값으로 판단한다.** 개발 PC GPU 성능이 아니라 HPC에서 잰 지연·메모리·전력을 쓴다.
- **모델도 소프트웨어처럼 서명하고 버전을 관리한다.** RAUC 번들(별도 슬롯 또는 artifact)로 배포하고, 이전 모델로 롤백할 수 있게 한다.

## 5. 테스트·검증

| 항목 | 방법 | 수준 |
| --- | --- | --- |
| 데이터 품질 | 라벨 샘플 검수, 분할 간 중복 검사 | 데이터 |
| 모델 성능 | 고정 test 세트, ODD 조건별 지표 | 오프라인 |
| 회귀 | 이전 모델 대비 지표 비교, 기준 미달이면 배포 중단 | 오프라인 |
| 변환·양자화 | 같은 입력에서 원본과 배포본의 출력 비교 | 오프라인 |
| 타깃 성능 | HPC에서 지연·메모리·온도 측정 | HIL |
| 통합 | 로봇·차량 시나리오 시뮬레이션, rosbag 재생 | SIL |
| 강건성 | 노이즈, 가림, 센서 고장 입력 | 선택 |

## 6. 관련 표준 (참고·준용 수준)

| 표준·법규 | 적용 부분 |
| --- | --- |
| ISO/PAS 8800 | 도로 차량 AI의 안전 생명주기, 데이터·모델 요구사항 |
| ISO 21448 (SOTIF) | 인지 한계로 인한 위험, ODD 정의 |
| ISO 26262 | AI가 안전 기능에 관여할 때의 상위 안전 요구사항 |
| EU AI Act | EU 시장 대상일 때 위험 분류·문서화 |
| 개인정보보호법, GDPR | 학습 데이터의 개인정보 |

## 7. 흔한 실수

- 학습·평가 데이터에 같은 주행 구간이 섞여 성능이 부풀려진다.
- 개발 PC에서만 측정해, 실제 장치에서는 지연 예산을 넘는다.
- 양자화 후 특정 조건(야간)에서만 성능이 크게 떨어지는데 평균 지표만 본다.
- 모델 파일을 서명 없이 별도 경로로 내려받아 업데이트한다.
- 어떤 데이터와 코드로 만든 모델인지 기록이 없어 문제를 추적하지 못한다.
